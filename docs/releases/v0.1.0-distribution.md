## NuGet candidate

Package ID/title: `LazyChromeWindowBridge.Core`; version: `0.1.0`.
Run `./Scripts/Test-NuGet.ps1` on Windows with PowerShell 7 and the pinned SDK.
The local consumer restores the exact local nupkg, not a project reference.
The package includes its MIT expression, README, project/repository metadata, tags
and the same reviewed 128px product icon as the extension. Matching portable symbols
are packed separately; the CLI's single nupkg push discovers the adjacent snupkg.

NuGet/login v1 was resolved through the official repository's annotated tag to
`8d196754b4036150537f80ac539e15c2f1028841`; the workflow pins that commit.
The tag is not cryptographically signed; “verified” here means the official tag
resolution and action content were checked, not a signature attestation.
Manual dispatch is restricted to the repository's main branch, exact dispatch SHA,
and environment `release`, with read-only contents and OIDC token permission.
No long-lived NuGet API key secret is used. See [NuGet instructions](../nuget.md).

## Chrome Web Store candidate

Run `./Scripts/Package-Extension.ps1`. Its current output is
`artifacts/cws/LazyChromeWindowBridge.Extension-0.1.0-cws.zip`; it no longer generates
the historical GitHub asset filename. The archive has fixed timestamps/order and
contains only six extension files plus four transparent PNG icons. Text is UTF-8/LF;
PNG bytes are preserved. Repeated generation must produce the same SHA256.

Run `./Scripts/Test-All.ps1 -Clean -ChromeExecutable <Chrome-for-Testing-executable>`.
All real browser modes load a fresh extraction of that exact audited ZIP, including
download lifecycle, native geometry, monitor recovery and five-session regression.
No production webpage automation was added; CDP evaluation in the test harness remains
test-only. See [listing, permissions and reviewer instructions](../chrome-web-store.md)
and the [privacy policy](../../PRIVACY.md).
