# v0.2.0 release notes

Chat accepted R012 distribution preparation from the accepted R010/R011 Source.
GitHub and NuGet 0.2.0 publication and the submitted CWS 0.2.0 artifact/review are now
historical, immutable state. This record describes that release; the working 0.3.0
R013 Source candidate is separate and unreleased.

## Changes since v0.1.0

- Continuous JPEG monitoring of live owned Visible and Parked windows through the
  same capture path, preserving previews across placement-only transitions.
- Per-session Pause/Resume through SetSessionMonitoring(Guid,bool). Paused retains
  the last JPEG as frozen, with unchanged Sequence/ReceivedAt; peers continue Live.
- Global Start/Stop remain batch controls. Stop clears all frames and retains waiting
  control sockets; next Start enables live sessions again. Dispose closes sockets.
- In-place FPS/output-size updates without resetting ordinary monitor generations,
  connections or same-tab debugger attachments. Explicit paused sessions stay paused.
- FPS requests 1–30 inclusive, default 2, default JPEG bounds 240x135 and fixed quality 70.
  Output bounds preserve aspect ratio without upscale or native/viewport/zoom changes.
- LCWB-launched Chrome requests --silent-debugger-extension-api for best-effort notice UX.
- Existing read-only, profile-global download lifecycle notifications remain supported.

PARK/RESTORE controls native window placement only. It never automatically starts,
stops, pauses or resumes monitoring. Monitoring policy belongs to the Caller, using
StartMonitoring / StopMonitoring / SetSessionMonitoring independently of Park / Restore.
Visible+Live, Visible+Paused, Parked+Live and Parked+Paused are all valid combinations.

The new public API and monitor contract expansion make 0.2.0 a feature release, not a
patch. Existing integration patterns are retained where tested; broader binary,
behavioral or Chrome-version compatibility is not promised by those tests.

## Boundaries and known limitations

Production debugger commands remain Page.getLayoutMetrics and Page.captureScreenshot.
Images are for human viewing only: no DOM/Runtime/Network inspection, OCR, semantic
analysis, automated webpage input or completion inference. No telemetry/cloud relay.
Debugger permission remains broad, and pixels/download filenames can be sensitive.

The third-display initial offscreen capture timeout remains unresolved. Chrome may
ignore the silent flag, and running profiles may retain original flags. Infobar visual
absence was not established as guaranteed behavior; capture does not depend on it.
30fps is a requested ceiling, not a throughput SLA. Existing restart/DPI/ownership/
download and bounded-shutdown limits remain in [limitations](../limitations.md).
