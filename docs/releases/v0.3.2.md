# v0.3.2 release notes — unpublished Source

Current Source v0.3.2 adds `BrowserKey`, `BrowserKeyModifiers`, `BrowserKeyChord`, and
`BridgeRuntime.SendKeyChordAsync` for one bounded allowlisted chord to the exact owned
window's active eligible tab. The extension maps the structured canonical request to a
fixed CDP `Input.dispatchKeyEvent` keyDown/keyUp pair and returns an explicit result.

This is not arbitrary JavaScript, arbitrary CDP, text entry, macro sequencing, click
automation, DOM automation, content inspection, or OS-global input. Completion means
the validated CDP dispatch completed; it does not guarantee page handling or Chrome UI
shortcut behavior such as Ctrl+L or Alt-based commands.

GitHub/NuGet v0.3.1 remains the latest published release. This document does not claim
GitHub, NuGet, or Chrome Web Store v0.3.2 publication.

## Distribution and version matching

Use matching Core and Extension versions; mixed-version compatibility is not guaranteed.
Chrome Web Store review can make a matching extension available later than GitHub/NuGet,
and LCWB does not guarantee every GitHub/NuGet version will be submitted to or published
on CWS. CWS is a convenient channel, not a complete archive of every LCWB version.

When CWS is behind or skips a version, download
`LazyChromeWindowBridge.Extension-0.3.2-cws.zip` from the matching GitHub Release,
extract it, open `chrome://extensions`, enable **Developer mode**, choose **Load
unpacked**, and select the extracted directory containing `manifest.json`. This exact
matching-extension installation path does not depend on CWS review or availability.
The extension is a developer companion rather than a standalone browser product: it has
no standalone dashboard or useful workflow without a matching LazyChromeWindowBridge
Windows/Core companion and authenticated owned sessions.
