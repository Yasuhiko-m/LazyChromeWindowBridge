# v0.3.1 release notes — publication pending

These are the prepared GitHub Release notes for the 0.3.1 working tree. Publication
remains pending Chat acceptance, checkpoint and Controller operations; this document
does not assert a GitHub, NuGet or Chrome Web Store publication. Historical 0.1.0/0.2.0
publication facts and the submitted CWS 0.2.0 review remain unchanged.

## Chrome launch policy

- LCWB launches add `--disable-backgrounding-occluded-windows` exactly once by default.
  This is intended to preserve rendering for an exact owned Chrome window when LCWB
  PARKs it fully offscreen, where Chrome supports the switch.
- `BridgeOptions.PreserveBackgroundRendering` defaults to `true`. Set it to `false` to
  omit only that LCWB policy switch.
- `BridgeOptions.AdditionalChromeArguments` is an ordered, default-empty caller switch
  collection. `BridgeOptions.Parse` also accepts repeatable `--chrome-argument <switch>`.
  Switches become structured launch arguments before LCWB's `--new-window`; the bootstrap
  URL remains the final positional argument.
- `--load-extension=<directory>` is allowed for Chrome for Testing or Chromium use. No
  claim is made that branded Chrome accepts that switch.
- LCWB rejects case-insensitive caller attempts to override user-data-dir, new-window,
  first-run, default-browser-check, silent-debugger-extension-api, or background-rendering
  launch invariants, including `=value` forms. Empty, positional and control-character
  values are also rejected.

Existing three-argument `BridgeOptions` construction remains source-compatible. The
accepted ownership, PARK/RESTORE, monitoring, NativeWindow no-fallback, taskbar and
download contracts are unchanged. Core, SampleCaller and Extension Source versions are
all 0.3.1; use matching Core and Extension versions.

## Capture region, resize and source-size refinement

0.3.1 adds a shared capture pipeline: natural source, a zero-based `CaptureRegion` grid selection, optional
`CaptureResize`, then JPEG quality 70. `GetCaptureSourceSizeAsync(id, mode)` is available
before monitoring; it is point-in-time CSS visual-viewport units for BrowserViewport and
native WGC pixels for NativeWindow, so callers use it primarily for aspect/layout planning.

`CaptureRegion` defaults to Full (1×1). Grid row/column origins are zero-based and spans
are positive; friendly Top/Bottom/Center presets belong in callers. Boundaries use floor
division so adjacent cells partition source pixels without gaps. With `Resize == null`,
the legacy MaxWidth/MaxHeight bounding box remains aspect-preserving and never upscales.
An explicit `CaptureResize` permits Width+Height distortion, a single dimension preserves
the selected-region aspect, and null/null retains natural cropped pixels. The only filters
are NearestNeighbor, Bilinear (default), and Bicubic; they express policy, not a promise of
pixel-identical kernels across canvas, D3D11, and drivers.

The current NativeWindow D3D11 VideoProcessor has no public sampler selection for
nearest-neighbor or bicubic. It accepts Bilinear through its established driver-native
scaling path; explicit NativeWindow NearestNeighbor and Bicubic requests fail before a
frame is published rather than being silently substituted. BrowserViewport supports all
three using OffscreenCanvas smoothing policy.

BrowserViewport obtains a natural PNG after `Page.getLayoutMetrics` without CDP clip,
scale, Emulation, or Chrome viewport resizing. The MV3 worker crops/resizes it with
OffscreenCanvas and sends only the final JPEG. NativeWindow applies the grid source rect
and resize on the exact-HWND WGC/D3D11 GPU path before bounded staging readback and CPU
JPEG encoding. A region change advances monitor generation to reject old pixels; ordinary
resize/filter updates remain in-place. The R015 occlusion-rendering launch policy remains.

## Preview liveness stability

V1-M010-R017 makes latest-frame and monitor-state reads observational cached snapshots:
frequent UI polling cannot itself reconcile geometry, cancel/restart a NativeWindow worker,
clear a completed JPEG, or advance generation. Monitor liveness now uses Bound state,
mapped non-Closed Visible/Parked placement, and exact retained NativeIdentity; a transient
failure to read current native bounds is geometry observability, not ownership loss.
Confirmed terminal placement/session state or an exact identity mismatch remains fail-closed.

## Compatibility and limitations

- BrowserViewport retains the existing Chrome debugger/extension binding; NativeWindow
  requires the supported Windows Graphics Capture/D3D11 exact-HWND path and never falls
  back to BrowserViewport.
- The documented initial offscreen-capture timeout on a third display remains unresolved.
  No monitoring throughput SLA is added: requested FPS remains a ceiling.
- NuGet distribution is Core-only. Use matching Core and Extension versions. The normal
  Store path is convenient only when it has the matching version; pending Store review,
  users instead obtain the matching extension ZIP from GitHub Release `v0.3.1`, extract
  it, and use Developer mode / **Load unpacked** at `chrome://extensions`.
