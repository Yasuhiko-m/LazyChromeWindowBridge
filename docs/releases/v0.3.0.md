# v0.3.0 release notes

V1-M007-R013 is the accepted 0.3.0 runtime baseline. R014 prepares the source,
packages and documentation for separately authorized GitHub Release and NuGet
publication. This file is publication-ready release content; it is not evidence that
the tag, Release, NuGet package, or Chrome Web Store 0.3.0 item already exists.

## Highlights

- Additive `CaptureMode`: default `BrowserViewport` preserves the 0.2.0 CDP capture
  behavior; `NativeWindow` captures the exact validated owned Chrome HWND through
  Windows Graphics Capture `CreateForWindow`, with no picker, candidate list, or
  replacement-window discovery.
- NativeWindow keeps capture GPU-first: WGC content-size crop and D3D11 resize bound
  the frame without upscale before CPU readback and GDI+ JPEG quality-70 encoding.
- Additive `SetShowInTaskbar(Guid,bool)` controls taskbar visibility only for the exact
  owned HWND. It is idempotent, independent of placement and monitoring, and restores
  the original style on normal disposal when LCWB changed it.
- SampleCaller exposes CaptureMode and selected-session taskbar visibility controls.

## Compatibility and boundaries

Existing BrowserViewport callers, including `new CaptureOptions(2, 240, 135)`, retain
their behavior. BrowserViewport continues to use only `Page.getLayoutMetrics` and
`Page.captureScreenshot`. NativeWindow requires Windows 10 version 1903/build 18362
or later and a compatible D3D11/WGC device; it fails explicitly when unavailable and
never falls back to BrowserViewport. The extension still declares debugger permission
for BrowserViewport compatibility.

PARK/RESTORE controls placement only; it never starts, stops, pauses, or resumes
monitoring. The caller owns live/paused policy. NativeWindow and BrowserViewport both
retain the bounded JPEG monitor contract: requested 1–30 FPS (default 2), default
240x135 bounds, aspect preservation, no upscale and JPEG quality 70. The known
third-display initial offscreen capture limitation remains unresolved.

Monitoring is for human viewing only. There is no DOM/Runtime/Network inspection,
automated webpage input, OCR, semantic analysis, recording, cloud relay or telemetry.

## Install the matching extension

NuGet ships `LazyChromeWindowBridge.Core` only; it does not contain the Chrome
extension. Install Core `0.3.0` from NuGet and use the matching extension version.
The Chrome Web Store is the normal convenient path when its matching version is
available. Store review can lag. If the Store does not have the matching 0.3.0
extension, download `LazyChromeWindowBridge.Extension-0.3.0-cws.zip` from GitHub
Release `v0.3.0`, extract it, open `chrome://extensions`, enable **Developer mode**,
choose **Load unpacked**, and select the extracted directory.

Historical GitHub/NuGet 0.1.0 and 0.2.0 publication facts, and the submitted CWS
0.2.0 review, remain unchanged. This release content does not claim CWS 0.3.0 approval
or publication. See [distribution preparation](v0.3.0-distribution.md).
