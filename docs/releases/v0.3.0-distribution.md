# 0.3.0 distribution preparation record

R014 prepares accepted V1-M007-R013 Source for a separately authorized GitHub v0.3.0
Release and NuGet `LazyChromeWindowBridge.Core` 0.3.0 publication. It records local
preparation expectations only: it does not create a tag, Release, package publication,
or Chrome Web Store operation. The submitted CWS 0.2.0 artifact/review and historical
GitHub/NuGet 0.1.0/0.2.0 facts remain untouched.

## Candidate artifacts

Use Windows, PowerShell 7 and SDK 10.0.400. Build only from the accepted publication
checkpoint after Chat acceptance, so NuGet repository metadata and Source Link refer to
that exact commit. `Scripts/Test-NuGet.ps1` performs the Release build, deterministic
Core/PublicApi/extension checks, package archive inspection and isolated local-feed
PackageReference consumer. `Scripts/Package-Extension.ps1` verifies deterministic
extension bytes; `Scripts/Package-Windows.ps1` creates and audits the self-contained
Windows x64 bundle.

| Asset | Candidate path |
| --- | --- |
| Core package | `artifacts/nuget/0.3.0/LazyChromeWindowBridge.Core.0.3.0.nupkg` |
| Portable symbols | `artifacts/nuget/0.3.0/LazyChromeWindowBridge.Core.0.3.0.snupkg` |
| Windows x64 bundle | `artifacts/release/0.3.0/LazyChromeWindowBridge-v0.3.0-win-x64.zip` |
| Extension asset | `artifacts/cws/LazyChromeWindowBridge.Extension-0.3.0-cws.zip` |

The GitHub Release uses the deterministic `-cws.zip` directly and the Windows x64
bundle directly. It does not need a duplicate extension alias or a second extension
payload. The protected inherited `src/LazyChromeWindowBridge.Extension.zip` is never
an input to packaging.

## Core-only NuGet and extension delivery

The NuGet package contains `LazyChromeWindowBridge.Core`, its two framework assets,
portable symbols, metadata, icon and package README only. It contains no extension
directory, extension ZIP, SampleCaller or installer. Users install Core 0.3.0 from
NuGet and use a matching Chrome extension.

The Chrome Web Store is the normal convenient route when its matching extension version
is available. Store review can lag. If the Store version does not match Core 0.3.0,
users download `LazyChromeWindowBridge.Extension-0.3.0-cws.zip` from GitHub Release
`v0.3.0`, extract it, open `chrome://extensions`, enable **Developer mode**, choose
**Load unpacked**, and select the extracted directory. This does not state or imply
that CWS 0.3.0 is approved or published.

## Publication boundary

The `publish-nuget.yml` workflow is manual-dispatch only, restricted to `main`, uses
the `release` environment and pinned actions, validates before OIDC Trusted Publishing,
and pushes exactly `LazyChromeWindowBridge.Core.0.3.0.nupkg` with its adjacent symbol
package. A duplicate version fails; there is no wildcard or `--skip-duplicate` path.

Controller publication, tag/release creation, NuGet authentication/push and all CWS
dashboard actions remain outside this R014 Source preparation.
