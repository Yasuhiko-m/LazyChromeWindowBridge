# LazyChromeWindowBridge v0.1.0

First public-release notes, prepared for the final accepted baseline. Publication is
not implied by this file. MIT licensed; early-release evidence and limits apply.

## Included
- Independent session/window binding: appSessionId → Chrome WindowId → exact native
  HWND/PID/property identity, preserved across navigation and same-URL multi-window use.
- Normal physical-pixel geometry persisted by original launch URL, manual Visible
  bounds, multi-monitor placement and reachable negative coordinates.
- Full offscreen PARK and exact RESTORE using the retained native window identity.
  Normal geometry is protected while PARKED; native shrinking is not used.
- Independent PARKED-only human thumbnails: default 2 fps, maximum 240×135, JPEG70.
  Visible windows have ACTIVE state with zero capture; the separate WinForms sample
  shows one tile per session. Core supplies encoded data without UI control dependencies.
- Chrome Download Manager Created / Complete / Interrupted notifications, exact official
  ID/path/error metadata, one profile-global stream per Bridge and no appSession attribution.
  Bounded session outbox and sequence deduplication recover ordinary worker restart and
  temporary loopback failure. Consumers perform post-Complete filesystem checks/moves.

## Permissions and boundaries
Manifest V3 permissions: storage, alarms, debugger and downloads; host access is
restricted to IPv4 loopback. Session capabilities authenticate the existing Kestrel
listener. Chrome debugger permission is broad and its normal notice is retained;
only viewport metrics/screenshots are used. The broad downloads permission is used
only for onCreated/onChanged/search. Absolute filenames can be sensitive and are not
logged by production code. No download mutation, DOM/Runtime/Network extraction,
OCR, semantic analysis, automated click/input or ChatGPT completion extraction.

## Tested environment
Windows desktop, .NET SDK 10.0.400, PowerShell 7.6.5, Node.js 24.19.0 and isolated
Chrome for Testing 153.0.8010.36. Chrome120+ is declared, not an exhaustive tested
version matrix. Real native placement uses three physical 96-DPI monitors, including
negative coordinates; mixed-DPI/topology edge cases have deterministic simulation.

The stable suite has 121 Core checks, 19 external public-API checks and 33 extension
tests. Real coverage includes session/navigation/close and worker recovery; geometry,
PARK/RESTORE/manual bounds; one ACTIVE plus four PARKED monitor streams and shutdown;
normal ZIP, deliberate interruption, five-session single download stream, worker
restart during download and consumer stable/exclusive checks and move after Complete.
The screenshot is an actual isolated neutral SampleCaller demonstration.

## Known limitations
- Windows-only; .NET10, ASP.NET Core and Windows Desktop shared runtimes are required.
- Initial offscreen capture can intermittently exceed the unchanged five-second
  acquisition budget. The affected session reports Error/detaches; explicit Start
  requests a new generation. Short passing runs do not eliminate this limitation.
- Other debuggers can contend for targets. Installed-Chrome consent is distinct from
  automated CfT testing; normal debugging notices are not suppressed.
- MV3 recovery is within the current browser session. Full browser/caller restart,
  extension reload/update and forced termination are not live-session takeover contracts.
- Download outbox/snapshots are bounded; overflow or loss of storage can lose events.
  There is no arbitrary history import, profile-to-session attribution or file safety
  guarantee. Synchronous handlers must return promptly. See [download limits](https://github.com/Yasuhiko-m/LazyChromeWindowBridge/blob/v0.1.0/docs/downloads.md).
- No installer, updater, Web Store publication or production-scale reliability claim.

## Extension asset
Extract LazyChromeWindowBridge.Extension-v0.1.0.zip to a dedicated directory, then
select that directory with Chrome's **Load unpacked**. manifest.json is at the ZIP
root. The asset contains only the six extension source files. The accepted extension
manifest remains version0.0.7; v0.1.0 identifies this distribution release, not a
new runtime version or automatic extension update. MIT terms are in the repository's
[LICENSE](https://github.com/Yasuhiko-m/LazyChromeWindowBridge/blob/v0.1.0/LICENSE); retain the copyright/permission notice when redistributing.
